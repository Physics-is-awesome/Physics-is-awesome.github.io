# Site Explanation (Physics-is-awesome.github.io)

This is Alex Cason's personal/research site. Right now there are two parallel "build artifacts" in the repo and the live site is using the **custom Python static site generator** in `alex-cason-site/`.

## What this site is
- **Live site**: https://physics-is-awesome.github.io/ (confirmed from webfetch - shows the new design with phase portrait, tiles, "Alex Cason." header)
- **Stack**: Pure static HTML/CSS/JS. No Jekyll framework for the actual content - custom generator using Jinja2 templates + Markdown (via `python-markdown` + `pymdown-extensions`) and LaTeX notes (converted via `pandoc` with `--mathjax`). Math rendered client-side with KaTeX.
- **Purpose**: Academic/personal site for an undergrad physics student at UTK. Sections: Home, Research, Projects, Notes (working knowledge base), YouTube, About, CV. Design system uses CSS variables in `alex-cason-site/src/static/css/style.css` (Spectral/Source Serif 4/IBM Plex fonts).

## Repo structure (important to understand)
```
Physics-is-awesome.github.io/
├── alex-cason-site/           # THE SOURCE + BUILD SYSTEM (active)
│   ├── build.py              # Generator - reads src/, writes dist/ (gitignored)
│   ├── requirements.txt      # Jinja2, Markdown, pymdown-extensions, PyYAML, python-frontmatter
│   ├── .github/workflows/deploy.yml  # GitHub Actions: builds with pandoc + deps, deploys dist/ to Pages
│   ├── src/
│   │   ├── templates/        # Jinja2 (base.html + page templates)
│   │   ├── content/
│   │   │   ├── pages/        # about.md, cv.md (Markdown + frontmatter)
│   │   │   └── notes/        # 24 .tex notes + _template.* (LaTeX notes)
│   │   ├── data/             # projects.yaml, videos.yaml, social-links.yaml
│   │   ├── static/           # css/style.css, js/main.js, img/, cv/
│   │   └── _pandoc-meta.tmpl
│   └── dist/                 # Built output (gitignored per .gitignore)
├── _site/                    # Committed built artifacts (older/parallel copies). On origin/main HEAD (8eb0277 "holding") these were just updated.
└── .bundle/                  # Bundler config (unrelated)
```

**Key point**: The active build system is `alex-cason-site/`. The root `_site/` also contains built files and is tracked on origin/main - there might be multiple deployment paths historically, but the design being served matches `alex-cason-site/src` exactly.

## What to edit
**For content (most common):**
1. **About bio/contact**: Edit `alex-cason-site/src/content/pages/about.md` (frontmatter + body). Add links to `alex-cason-site/src/data/social-links.yaml` (as soon as non-empty they appear on About).
2. **CV**: Add PDF to `alex-cason-site/src/static/cv/your-cv.pdf`, then edit `alex-cason-site/src/content/pages/cv.md` to uncomment the download link.
3. **Notes**: Add `your-slug.md` (with frontmatter: title/date/tags/summary) or `your-slug.tex` (with optional `% tags: ...` and `% summary: ...` at top). LaTeX needs pandoc. Filename becomes URL (`notes/your-slug.html`). Don't start filenames with `_` (templates are ignored).
4. **Projects**: Edit `alex-cason-site/src/data/projects.yaml` - add entries with title/status/tagline/description/tags/github/paper/notesLink/linkLabel. Empty strings hide buttons.
5. **Videos**: Edit `alex-cason-site/src/data/videos.yaml` - set `channel_url` for subscribe link, add video entries.
6. **Research page**: Edit `alex-cason-site/src/templates/research.html` - replace placeholder with cluster blocks (CSS classes already styled, KaTeX loaded).

**For styling/structure:**
- **Colors/fonts/spacing**: `alex-cason-site/src/static/css/style.css` - all CSS custom properties at top
- **Templates/layout/nav**: `alex-cason-site/src/templates/` (base.html has header/nav/footer). All pages extend base.html.
- **Client behavior**: `alex-cason-site/src/static/js/main.js` (search/tags for notes, rendering projects/videos/contact from JSON data files)

**For the notes system:**
- The LaTeX notes are huge and already converted (24 notes exist). When adding LaTeX notes, be aware pandoc converts them; cross-refs with `\label/\ref` aren't resolved (write as plain text). The build auto-extracts title from `\title{}`, date from `\date{}` via the pandoc template, and tags/summary from comments.
- Note titles in index get derived from filename slug (underscores become spaces/title case) if not in frontmatter.

**Deployment:**
- The repo has `alex-cason-site/.github/workflows/deploy.yml` which builds on push to main: installs deps + pandoc, runs `python build.py`, uploads `dist/` to Pages. This is the clean way.
- Root has `_site/` committed - be careful not to confuse which one is the source of truth. The live site matches the alex-cason-site design; the workflow deploying from alex-cason-site/dist/ is likely what's used.

## How to change (workflow)
**Local development:**
```bash
cd alex-cason-site
pip install -r requirements.txt  # or use venv
python build.py                  # builds to dist/
python build.py --serve          # builds and serves at http://localhost:8000
```
Pandoc is required for `.tex` notes (install via `apt install pandoc` / `brew install pandoc`). Markdown notes don't need it.

**Making changes:**
1. Edit files in `alex-cason-site/src/` (never edit `dist/` directly)
2. Test locally with `build.py --serve`
3. Commit changes to source files in `alex-cason-site/` and push to `main`
4. GitHub Actions will rebuild and deploy automatically

**To update the root `_site/` copies** (if they're still used/committed): you'd need to copy built output there too, but better to stick to the alex-cason-site workflow.

The site is functional as-is - just needs content filled in. Start with About, add social links, populate Research/Projects/Videos as you go. The notes infrastructure is already fully working with search and tags.
